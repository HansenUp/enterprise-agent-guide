# 1 技术演进与迁移判断

## 演进不是简单的替代链

早期专家系统、规则引擎和工作流解决明确规则下的自动化。LLM 增加了自然语言理解与生成，RAG 增加外部知识，工具调用增加操作能力；Agent Loop 再依据环境反馈选择下一步。生产化阶段进一步补上持久状态、权限、验证、恢复和治理。它们可以组合，后一个阶段不会自动淘汰前一个阶段。[S01][S02][S03]

2022—2023 年的 ReAct、思维树和反思方法把推理、动作及反馈组织起来。2024—2025 年，结构化工具调用、可组合工作流、检索与工具协议逐步降低接入成本。2025—2026 年，工程重点进一步转向上下文、长期任务、评测、执行隔离和可替换的 Harness。[S01][S03][S04][S05]

## 有官方依据的迁移事项

- OpenAI Assistants API：官方列出的关闭日期是 2026 年 8 月 26 日，该日期已过；新方案应采用其推荐的 Responses 与 Conversations 接口。这里引用官方生命周期记录，并非对每个旧账户做实际探测。[S06]
- MCP：本次核验 latest 指向 2026-07-28。新规范与 2025-11-25 存在实质差异；不要拼接两个时代的握手、会话、通知和任务示例。[S07][S08]
- MCP 旧 HTTP+SSE 传输，以及 Roots、Sampling、Logging 功能在所核验规范中列为 Deprecated；“旧 HTTP+SSE 被弃用”不等于 SSE 技术被淘汰。迁移细节见第 10 章。[S08]
- Microsoft AutoGen 官方仓库标为维护模式，不再增加功能，建议新项目采用 Microsoft Agent Framework。Semantic Kernel 的继任方向也指向该框架，但不能据此一概声称全部旧能力已停止运行。[S09][S10]

## 应减少默认使用但并未正式弃用

超长万能 Prompt、无限自我反思、所有任务都开多 Agent、把全部历史塞进上下文、仅靠向量相似度决定业务事实、让模型自由拼接并执行写库 SQL：这些做法的适用范围应收窄。原因是可验证性、成本和权限边界，而不是名称不够新。

RAG、BPMN、传统 NLP、规则引擎、单 Agent 与微调都没有整体过时。品牌打标可以用 LLM 解决复杂语义，再让规则或小模型处理稳定部分；CRM 查询常常只需要受控工具和短工作流。

## 值得持续投入的方向

高置信度工程方向：受控工具、业务身份、持久执行、证据链、评测回归和可观测性。

中等置信度发展方向：动态上下文、按需工具发现、技能包、程序化工具编排和独立运行时。

条件性前沿方向：跨组织 Agent 协作、递归上下文处理、长时自主任务和策略学习。是否成为主流仍取决于业务收益、互操作成熟度及治理成本。
