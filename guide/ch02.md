# 2 基本构成与能力边界

## C001 Agent（智能体） 【基础】

Agent 是围绕目标观察环境、选择动作、使用工具并根据结果继续行动的软件系统。企业讨论中宜把“模型能否决定下一步”作为边界，而不只看是否有聊天界面。给菜单打标的一次模型调用是 AI 应用，但未必需要自治 Agent。[S01]

## C002 Agentic Workflow / Deterministic Workflow（智能体工作流／确定性工作流） 【基础】

工作流预先规定步骤和分支，模型完成其中的理解、生成或局部决策；Agentic Workflow 是较宽泛称呼，并无全行业统一定义。审批、结算、入库等硬规则应落在代码或流程引擎中。可预测业务采用工作流通常更容易验收，不是落后方案。

## C003 Copilot / Autonomy Levels（协作助手／自主等级） 【基础】

Copilot 通常把建议交给人执行；自主 Agent 可以在授权范围内执行动作。推荐自行划分“只读分析、生成草稿、确认后写入、限额自动执行”四级，它是平台治理分级，不是通用国际标准。级别应按动作风险设置，而不是给整个模型贴一个权限标签。

## C004 Agent Loop（智能体观察、决策与行动循环） 【基础】

一次循环包含获取任务状态、构建上下文、模型决策、验证调用、执行工具及检查结果。停止条件包括成功证据、预算耗尽、取消、等待输入或不可恢复故障。while 循环只是代码外观；最大步数、失败判定、状态落盘才决定能否可靠运行。

## C005 Harness（运行约束与执行框架） 【增强】

Harness 包含模型外部的任务推进、上下文组装、工具分派、验证、恢复和预算控制；术语在不同项目中边界略有差异。它不同于一份 Prompt，也不要求固定节点或角色数量。用评测证明每个节点的作用，模型升级后删除无收益的补丁。[S03][S04]

## C006 Model / Tool / Environment（模型／工具／环境） 【基础】

模型提出动作；工具提供可执行契约；环境保存真实资源和反馈；运行时控制能否执行。模型声称“客户已更新”不构成成功，必须由 CRM 的结果或后续查询验证。把这四者分离，可单独升级模型、替换连接器或重建沙箱，避免把全部状态绑定在一个进程。[S05]

工程练习：把“分析客户并安排回访”拆成只读数据获取、建议生成、用户确认、创建回访任务和结果核验；指出哪些步骤需要模型，哪些不需要。
