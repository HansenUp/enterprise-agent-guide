# 3 模型与推理的基础

## C007 Token / Context Window（词元／上下文窗口） 【基础】

Token 是模型处理文本等输入的计量单元，不等于汉字或单词。上下文窗口是一次推理可处理的输入与相关输出容量约束，规则依模型而异。容量大不代表所有位置的信息都能同样可靠地利用；平台要预算系统指令、工具定义、检索内容、历史和输出。

## C008 Autoregressive Generation / Sampling（自回归生成／采样） 【基础】

常见语言模型逐步生成后续 Token。Temperature、top_p 等参数影响输出分布，但可用参数和语义因模型而异。temperature 为零不保证跨版本、跨服务实例绝对确定，也不能使错误事实变正确。稳定生产应依靠结构校验、版本固定与回归测试。

## C009 Reasoning Model / Reasoning Budget（推理模型／推理预算） 【增强】

推理模型可能在回答前投入更多内部计算；可配置的推理强度是质量、时延和成本的取舍。复杂分析可以受益，简单打标未必需要最高档。内部推理过程不等于可审计业务依据；向用户提供来源、约束、结论和可验证步骤即可。[S11]

## C010 Multimodality（多模态）/ ASR（Automatic Speech Recognition，自动语音识别）/ OCR（Optical Character Recognition，光学字符识别） 【基础】

多模态模型可以处理文字、图像、音频等；ASR 将语音转文本，OCR 提取图中文字。CRM 录音还涉及说话人分离、时间戳、专有名词纠错与实体关联。转写是有误差的数据源，客户承诺、数量和商品名要能定位回原录音片段，不应被当成绝对事实。

## C011 Embedding / Reranker（嵌入表示／重排模型） 【基础】

Embedding 把文本等映射为向量，便于相似性检索；Reranker 对候选与问题的相关程度重新评分。两者通常不是同一模型。向量距离不等于业务置信概率。更换 Embedding 后一般需要版本化索引并重建相应向量，不能无验证混用不同向量空间。

## C012 Model Routing / Capability Matrix（模型路由／能力矩阵） 【增强】

按任务复杂度、隐私要求、语言、结构化输出、工具能力与成本选模型。网关应维护能力矩阵，而不是把所有供应商当作同一个接口。主模型失败时，降级模型可能不支持相同 Schema、上下文或工具并发，需要回退到受限方案而非悄悄降质。

架构建议：不要在指南中永久固定“最强模型”。维护带日期的企业评测榜，至少比较完成率、错误动作率、p95 完成时延与每次成功任务成本。
