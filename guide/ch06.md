# 6 记忆与知识边界

## C025 Session / Thread / Run（会话／对话线程／任务运行） 【基础】

Session 或 Thread 通常承载连续交互，Run 表示一次任务执行；供应商命名不完全一致。它们不等于模型上下文窗口。一次会话可跨多次任务，多轮模型调用也可服务同一任务。企业平台应自定义稳定标识，避免把业务数据主键绑定到供应商线程 ID。

## C026 Working Memory（工作记忆） 【基础】

保存当前任务的临时状态、已读证据、工具结果与未完成步骤。适合放在结构化任务状态和可恢复存储中，部分内容按需进入 Prompt。缓存被清理不应导致任务事实永久丢失；短期记忆也应有租户和会话隔离。[S15]

## C027 Semantic Memory / Episodic Memory（语义记忆／情景记忆） 【条件】

语义记忆保存相对稳定的事实；情景记忆保存某次交互或事件经历。客户主营川菜可以是待确认事实，上次因配送范围未成交是带时间的事件。保存来源、有效期和确认状态，客户变更经营方向后应覆盖或失效旧信息。[S15]

## C028 Procedural Memory / Skill（程序性记忆／技能） 【增强】

程序性记忆保存做事方法，如新品分析流程或发布检查清单。可实现为经审查的技能包、规则或模板，不必采用向量库。将单次成功经验直接推广为通用规范容易误导；需要适用条件、反例、版本与维护人。[S15][S16]

## C029 Memory Lifecycle（记忆写入、合并与遗忘） 【基础】

记忆生命周期包括候选提取、验证、去重、冲突处理、更新、过期与删除。模型说“用户喜欢高价商品”不应自动成为客户永久标签。建议敏感或影响业务判断的事实经过业务确认，并让删除同步到缓存、向量索引和衍生摘要。

## C030 Source of Truth / Knowledge Base / Memory（权威事实源／知识库／记忆） 【基础】

业务事实源如 CRM、ERP 保存权威状态；知识库提供制度和参考资料；Agent 记忆保存交互经验。三者不能合并为一张“万能向量表”。库存、价格、授信与合同状态查询应回到业务系统，记忆可辅助理解但不能覆盖权威记录。

设计例：客户画像表同时保存“事实字段”“推断字段”“最后验证时间”。跟进建议引用事实，但不把建议自动回写成已发生事件。
