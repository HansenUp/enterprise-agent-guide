# 7 检索与知识工程基础

## C031 RAG（Retrieval-Augmented Generation，检索增强生成） 【基础】

先从外部数据检索相关证据，再让模型生成答案。RAG 的核心价值是可更新的外部知识和证据，而不只是向量数据库。权限、时效与可追溯仍使它有价值；长上下文和微调不会自动替代这些能力。[S17]

## C032 Ingestion（数据摄取）/ ETL（Extract, Transform, Load，抽取、转换与加载）/ CDC（Change Data Capture，变更数据捕获） 【基础】

Ingestion 把文件与业务数据纳入知识管道；ETL 做抽取转换加载，CDC 捕获增量变更。必须处理解析失败、重复文档、版本更新和删除传播。记录来源 ID、租户、权限和更新时间，避免源文件删了而索引仍可检索。

## C033 Chunking（文档切分） 【基础】

按段落、标题、语义或结构切分材料，控制检索粒度。太小会丢失上下文，太大增加噪声。父子块可用小块检索、较大段落回答；表格应保留列名、单位与表头，合同应保留条款归属。切分策略是数据工程选择，不是一个万能固定字数。

## C034 Dense Retrieval / Sparse Retrieval / Hybrid Search（稠密检索／稀疏检索／混合搜索） 【基础】

Dense 检索利用向量语义相似度；Sparse 如 BM25 利用词项匹配；Hybrid 综合两类候选。商品型号、品牌名和内部编码常需要精确匹配。RRF 按排名融合，不直接假设两种分数可相加；召回结果仍要权限过滤与后续排序。[S18]

## C035 ANN（Approximate Nearest Neighbor，近似最近邻）/ HNSW（Hierarchical Navigable Small World，分层可导航小世界）/ Vector Index（向量索引） 【基础】

近似最近邻检索用速度和内存换取一定召回损失，HNSW 是常见索引方法。评估必须在真实过滤条件、数据量和并发下进行。索引参数提高并不必然提升最终回答质量；瓶颈也可能是切分、Embedding、权限过滤或问题理解。

## C036 Metadata Filter（元数据过滤）/ ACL（Access Control List，访问控制列表） 【基础】

元数据过滤用于限定客户、部门、时间、文档状态等；ACL 表达访问权限。权限必须来自受信身份，不能让模型自行填 tenant_id 决定范围。检索、缓存、引用和答案导出应保持同一权限约束，防止过滤前的候选通过日志或摘要泄露。

工程练习：构造两个租户拥有同名商品的测试，验证检索、答案缓存、引用下载和历史会话均不会串租户。
