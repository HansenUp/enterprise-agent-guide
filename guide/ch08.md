# 8 检索增强与事实校验

## C037 Query Rewriting / Query Decomposition（查询改写／查询分解） 【条件】

查询改写把口语问题转为更适合检索的表达；分解将复杂问题拆成子问题。客户说“上次那个货”时可结合近期记录定位商品。改写必须保留原始约束，不能将“不含辣椒”变成“辣椒相关”。衡量召回收益及增加的时延，而非改写次数。

## C038 Reranking / Contextual Compression（重排／上下文压缩） 【增强】

重排提高候选相关性；上下文压缩删除无关片段。它们解决的不是同一个问题。推荐先保证召回，再用重排和证据级筛选控制输入长度。压缩应保留原文引用和数值，避免“符合条件的证据”被压成“模型认为符合”。

## C039 Agentic RAG / Adaptive Retrieval（智能体驱动的检索增强生成／自适应检索） 【条件】

由 Agent 决定查什么源、是否继续查、何时停止。适合多跳或来源不明确的问题；固定 FAQ 常用两阶段 RAG 更便宜。设置最大检索轮数、证据覆盖要求及失败出口。Agentic RAG 是编排模式，不是必须使用某一款新数据库。

## C040 Self-RAG / Corrective RAG（自反思检索增强生成／纠正式检索增强生成） 【条件】

Self-RAG 的原始研究把检索与自评信号纳入模型训练；工程界也常用相似名称表示“检索后检查再补查”。两者不能混为一谈。纠正性检索关注检测低质量材料后补查或换源。仅让同一模型反复说“答案正确”不能构成独立验证。[S19]

## C041 GraphRAG / Ontology（图检索增强生成／本体） 【条件】

GraphRAG 利用实体关系及相关摘要辅助跨文档分析；Ontology 定义业务实体、关系和约束。适合品牌归属、供应关系、跨客户关联等问题，不必用于每个问答。图抽取错误会传播，构图与更新也有成本；先证明多跳或全局问题优于普通检索。[S20]

## C042 Text-to-SQL / Semantic Layer（自然语言转 SQL／语义层） 【条件】

Text-to-SQL 将自然语言转为查询，语义层定义指标、维度及统一口径。企业应优先暴露经过审查的查询工具和只读视图，限制表、列、扫描量与执行时间。SQL 语法正确不代表口径正确，例如销售额是否扣退款、按下单还是履约日期计算。

业务原则：销售统计交给 SQL 或分析引擎计算，LLM 负责解释、发现待验证问题及生成建议；不要让模型从大量流水文本中心算营业额。
