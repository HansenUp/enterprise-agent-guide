# 10 协议与互操作的现行边界

## C049 MCP（Model Context Protocol，模型上下文协议） 【增强】

MCP 用共同消息约定连接 Host、Client 与 Server，并暴露 Tools、Resources 和 Prompts。Host 是应用，Client 是连接侧组件，Server 提供能力。它减少集成格式差异，但不自动解决业务权限、工具质量、持久任务及事务一致性。[S07]

## C050 MCP Transport / Capability Negotiation（MCP 传输／能力协商） 【迁移】

核验的 2026-07-28 规范采用无状态请求与每请求能力元数据，并提供 server/discover；不应继续把旧 initialize 握手和 Mcp-Session-Id 当作新实现前提。stdio 适合本地子进程，Streamable HTTP 适合服务连接；可含 SSE 响应流，区别于旧 HTTP+SSE 传输。[S08][S23]

## C051 Roots / Sampling / Logging（根目录声明／采样请求／日志） 【迁移】

Roots 原用于描述根目录范围，Sampling 允许服务侧请求模型采样，Logging 是协议日志能力。这三项在核验版本中进入弃用期，并非立刻在所有客户端消失。新实现优先采用显式资源参数、直接模型调用和独立日志观测；不要依赖 Roots 作为操作系统沙箱。[S08]

## C052 Tasks / Elicitation / MCP Apps（任务／信息征询／MCP 应用） 【增强】

Tasks 提供长操作句柄，现行规范把它移入扩展；Elicitation 获取缺失信息，MRTR 将补充输入组织为请求重试；Apps 提供会话内交互 UI。它们都不能替代企业任务库和审批账本。扩展需核验双方实现，不能根据“支持 MCP”推定全部可用。[S07][S08]

## C053 A2A（Agent2Agent，智能体间协议）/ Agent Card（智能体能力卡片） 【增强】

A2A 面向独立 Agent 之间的发现、消息、任务及产物交换，Agent Card 描述能力与接口。规范已发布 1.0 系列（2026 年 10 月复核时最新为 v1.0.1），协议交互使用主次版本如 1.0；0.3 示例不能直接当 1.0 使用。它与 MCP 可互补，但内部子 Agent 不必经过 A2A。[S24]

## C054 Agent Skills / Plugin / Registry（智能体技能／插件／注册目录） 【增强】

Skill 是任务知识、指令及可选脚本资源的可复用包，Agent Skills 规范以 SKILL.md 等组织并支持渐进加载；Plugin 是产品级包装，可能含技能和连接器；Registry 负责发现与版本信息。可发现不等于可信，应审查来源、依赖、权限和适用边界。[S16]

迁移提醒：MCP DCR 在所核验版本中被弃用但保留兼容，推荐方向包括 Client ID Metadata Documents；授权实现按具体规范和服务能力匹配。[S25]
