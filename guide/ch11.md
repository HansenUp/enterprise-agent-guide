# 11 Planning and Control Patterns（规划与控制模式）

## C055 ReAct（Reasoning and Acting，推理与行动） 【基础】

ReAct 将推理与动作交替，让环境反馈影响下一步。今天可以由原生工具调用表达，不必用正则解析 Thought / Action 字符串。应继承“行动后看真实反馈”的思想，避免把某种早期文本模板当成永久协议。[S26]

## C056 Plan-and-Execute（规划与执行） 【条件】

先形成计划，再逐步执行并按反馈重规划。适合跨系统、多步骤任务；简单查询无需单独规划模型。计划应记录目标、依赖和成功条件，不能把计划本身当作事实。客户资料变化或工具失败后，重新规划范围必须受原授权约束。

## C057 Routing / Chaining（路由／链式调用） 【基础】

Routing 把请求分到合适分支，Chaining 串联固定步骤。可先判断是客户查询、商品推荐还是工单操作，再进入不同流程。对低置信路由增加澄清或人工入口。不要为了所有分支统一而制造一个包含全部业务规则的巨型 Agent。[S01]

## C058 FSM（Finite State Machine，有限状态机）/ DAG（Directed Acyclic Graph，有向无环图）/ BPMN（Business Process Model and Notation，业务流程模型与标记） 【基础】

有限状态机表达合法状态转移，DAG 表达无环依赖，BPMN 常用于业务流程与人工作业。Agent 会有循环与等待，纯 DAG 未必够用。建议用确定性外层处理审批、超时和补偿，模型在有限节点中决策；图节点多不等于架构先进。

## C059 Reflection / Evaluator-Optimizer（反思／评估器与优化器） 【条件】

Reflection 根据反馈改进；Evaluator-Optimizer 由评估者提供改进方向。原始 Reflexion 研究使用反馈文本与记忆，不等于模型权重更新。应优先使用单测、业务规则、可信检索或人工反馈；仅让同模型互相夸赞会形成虚假闭环。[S27]

## C060 ToT（Tree of Thoughts，思维树）/ Search / Test-Time Compute（搜索／测试时计算） 【条件】

思维树探索多个候选路径；搜索可能加入剪枝、评分或回溯。推理时增加计算有时提高成功率，却也增加成本并可能优化错误指标。适合可评分的复杂规划；企业常规任务先比较强模型单次方案与少量候选验证，避免默认大规模树搜索。[S28]

控制原则：探索自由度可以增加，但写操作的权限边界、预算上限与成功判定不能交给同一轮自然语言自评。
