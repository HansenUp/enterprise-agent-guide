# 13 运行时与长期任务

## C067 Agent Runtime（智能体运行时） 【基础】

Runtime 管理任务接收、循环执行、并发、暂停恢复、预算、工具路由与产物。SDK 提供构建接口，不自动等于完整生产运行时。企业需明确哪些职责由框架承担，哪些由平台服务承担，避免把进程内存中的聊天历史当成持久执行。

## C068 Durable Execution（持久化执行） 【增强】

持久执行在进程故障、网络中断或长时间等待后恢复任务。检查点、事件历史和幂等副作用共同实现它。LangGraph 提供持久化机制，Temporal 提供可恢复工作流；二者抽象不同，不应不加设计地同时管理同一层重试。[S29][S30]

## C069 Checkpoint / Resume / Replay（检查点／恢复／重放） 【基础】

Checkpoint 保存状态，Resume 从可恢复点继续，Replay 根据已记录事件重建执行。恢复模型请求若重新采样，可能产生不同计划；关键响应应记录版本和原始结果。重放不应重复发送邮件、创建订单或执行支付，需要副作用账本配合。

## C070 HITL（Human-in-the-Loop，人在回路） 【基础】

人在关键节点提供澄清、审批或纠正。审批应绑定具体对象、参数、版本和有效期；批准一份推荐不等于批准以后所有订单。流程暂停不能持有数据库事务。恢复时重查身份和业务状态，防止审批期间客户归属或价格已经改变。

## C071 Artifact（执行产物） 【基础】

Artifact 是结构化报告、代码、文件、清单或可验证业务结果。它应独立于临时聊天保存，包含版本、归属、来源和访问策略。长期任务以产物交接比口头总结可靠，但产物仍需检查完整性；文件存在不等于任务通过验收。

## C072 Scheduling / Budgeting / Cancellation（调度／预算／取消） 【基础】

调度处理优先级、队列、公平性和工作者分配；预算限制 Token、工具次数、运行时间及金额。取消要向下游传播，但“收到取消”不代表远端副作用撤销。设置明确的等待、超时、已取消及结果未知状态，让业务人员能辨认真实进度。

运行时最小验收：杀死执行进程后恢复任务，确认不会重复创建业务记录；暂停一天后恢复，确认权限和业务数据会重新核验。
