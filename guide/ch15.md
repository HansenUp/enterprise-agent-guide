# 15 安全与执行边界

## C079 Prompt Injection（提示注入） 【基础】

攻击或意外文本把数据伪装成指令，来源可能是网页、录音转写、邮件、知识片段或工具描述。隔离指令与数据、限制可用工具、验证每次动作和减少可读取凭证是基础。检测模型只能降低风险，不能保证识别所有注入。[S14]

## C080 Least Privilege / Capability Boundary（最小权限／能力边界） 【基础】

最小权限把 Agent 能做的事限制在当前任务所需范围。优先授予具体工具动作和资源范围，而非整个管理员账号。权限由受信身份服务计算；模型可以提出请求，但不能给自己扩权。工具列表隐藏是减少误用，真正授权仍需服务端执行。

## C081 Sandbox / Egress Control（沙箱／出站控制） 【基础】

沙箱隔离生成代码的文件、网络和进程访问；出站控制约束数据发送目的地。容器只是隔离手段之一，不自动保证安全。按风险选进程隔离、容器或更强虚拟化，限制资源，避免暴露宿主控制接口。将凭证存放在沙箱外代理中更利于控制。[S05]

## C082 Tool Poisoning / Supply Chain Security（工具投毒／供应链安全） 【基础】

工具或技能描述、依赖包、返回内容可能被篡改并诱导越权。注册中心应保存发布者、版本、哈希、审查记录和撤销状态；变更工具描述也应触发评测。签名证明来源与完整性，不证明内容本身正确或无害。

## C083 Guardrail / Policy as Code（护栏／策略即代码） 【基础】

Guardrail 是输入、输出或过程检查；Policy as Code 用确定性规则表达授权、限额、数据范围和发布门槛。两者可以组合。把“不能下单”写进 Prompt 是行为引导，撤销下单工具权限才是执行约束；规则失败应进入明确的拒绝或人工流程。

## C084 Data Exfiltration / Output Handling（数据外泄／输出处理） 【基础】

数据外泄可能通过工具参数、网页请求、附件或日志发生。检查输出目的地与数据类别，对下载链接、HTML、SQL 和代码按其使用环境处理。模型生成的文本不能直接拼接成 shell 或数据库指令。防护应覆盖“读到什么”和“能发到哪里”。

评测要求：模拟恶意知识文档请求导出客户表，检查系统是否在工具执行层阻断；不要只看模型回复中有没有说“我不能”。
