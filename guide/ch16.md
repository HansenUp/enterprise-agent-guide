# 16 身份与治理

## C085 Authentication / Authorization（身份认证／访问授权） 【基础】

认证回答“你是谁”，授权回答“你可以对什么做什么”。服务账号、用户代理身份和 Agent 实例应可追踪关联。MCP 的 OAuth 流程提供连接授权机制，不能替代 CRM 的行级与字段级权限。OAuth 2.1 的标准状态以所引用规范为准，不能随意称为已发布 RFC。[S25]

## C086 Delegation（委托授权）/ OBO（On-Behalf-Of，代表用户执行） 【基础】

委托让系统代表用户执行限定操作。应记录原始用户、当前执行服务、授权范围和期限；跨 Agent 委派不能隐式放大权限。机器人发起的任务与员工发起的任务可能有不同政策，审计中必须能辨认主体与责任人。

## C087 Multi-Tenancy / Isolation（多租户／隔离） 【基础】

租户隔离覆盖任务、知识、向量索引、记忆、缓存、对象存储、配额和日志。共享物理资源可以降低成本，但隔离逻辑必须集中实现并测试。tenant_id 不应信任模型输出；异步消息携带的租户上下文也需要校验来源。

## C088 Secrets Management / Vault / Credential Broker（秘密管理／凭据保险库／凭据代理） 【基础】

凭证不进入 Prompt、工具描述或普通日志。短期令牌、外部密钥库与代理调用可减少泄露范围。凭证轮换或撤销后，恢复中的长期任务应重新获取授权；不能把“任务开始时可用的令牌”视为整个生命周期永远有效。

## C089 Data Classification / Retention / Deletion（数据分级／保留／删除） 【基础】

区分公开、内部、客户敏感及受限数据，定义可用模型部署位置、日志保留与访问规则。删除应传播到源数据副本、向量、摘要、记忆和缓存。数据驻留不等于所有风险消失；本地模型同样需要防止内部越权和不当导出。

## C090 Control Plane / Data Plane（控制面／数据面） 【基础】

控制平面管理配置、策略、模型路由、工具注册和发布；数据平面执行任务与业务访问。控制平面变更需审批和审计，数据平面需要低时延与故障隔离。分离两者有助于共享治理、独立扩容，并防止业务 Agent 改写自身安全策略。

制度建议：为每个 Agent 指定业务负责人、技术负责人、风险等级、可写工具、数据范围、验收指标、应急停用方式和下线计划。
