# 17 评测体系

## C091 Task Success / Trajectory Evaluation（任务成功／执行轨迹评测） 【基础】

结果评测检查任务是否完成，轨迹评测检查工具调用、权限、步骤和副作用是否正确。回答正确但读取了其他租户数据，仍然失败。为不确定系统做重复试验：pass@k 关注多次尝试至少一次成功，pass^k 关注多次全部成功；企业自动执行更需要稳定成功而非偶尔成功。[S31]

## C092 Golden Set / Holdout Set / Data Leakage（基准集／留出集／数据泄漏） 【基础】

黄金集是人工核验的代表性样本；开发集用于迭代，保留测试集用于最终验证。按客户、时间或业务实体切分，避免同一客户相似记录同时进入训练和测试。数据集应包含正常、歧义、缺失、拒绝和异常样本，并按难度与风险分层。

## C093 Retrieval Metrics / Generation Metrics（检索指标／生成指标） 【基础】

Recall@k 衡量需要的相关材料是否被召回，Precision@k 衡量前 k 条有多少相关；MRR 看首条相关结果位置，nDCG 考虑排序和分级相关性。生成层另外评估事实正确、证据支持、引用定位和覆盖率。检索好不保证回答好，答案流畅也不能反证检索准确。

## C094 Classification Metrics / Calibration / Selective Prediction（分类指标／校准／选择性预测） 【基础】

Accuracy 容易被大类别占比掩盖；Precision、Recall、F1 和混淆矩阵应按类别报告，宏平均用于观察小类别。Calibration 检查置信程度与实际正确率是否匹配。不能直接把模型自报“98% 确信”当概率；可以用验证集校准并设拒答、人工复核区间。

## C095 LLM-as-a-Judge（Large Language Model as a Judge，大语言模型评审）/ Human Review（人工评审） 【条件】

模型裁判适合规模化检查主观质量，但存在位置、表达长度、自偏好和评分漂移。制定可操作评分表，随机化顺序，与盲评人工样本校准；关键权限与财务状态用确定性检查。裁判、业务模型和数据集均需版本化，不能只保存一个总分。

## C096 Regression Testing / Red Teaming / Ablation Study（回归测试／红队测试／消融实验） 【基础】

回归集保留历史失败，红队主动设计恶意输入与边界攻击；消融实验逐项移除检索、反思、子 Agent 等机制，检验其实际贡献。上线前同时检查正常任务表现和越权阻断。失败样本修复后回归，不能通过删除难例让评分变好。

验收表应同时记录：任务成功率、严重错误率、人工接管率、每次成功成本、P95 时延、样本数、测试时间及版本。没有分母和切分方式的百分比不宜作为架构优劣依据。
