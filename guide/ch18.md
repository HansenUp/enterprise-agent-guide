# 18 可观测性与发布

## C097 Trace / Span / Correlation ID（调用链／追踪单元／关联标识） 【基础】

Trace 连接一次任务的模型、检索、工具和子任务；Span 表达其中一段工作。记录耗时、token、输入输出摘要、错误码和版本，敏感内容按策略脱敏。OpenTelemetry 适合统一链路；GenAI 语义约定仍需按实际版本管理，不能假定所有厂商字段已稳定互通。[S32]

## C098 Observability / Evaluation（可观测性／评测） 【基础】

可观测性解释“发生了什么”，评测判断“做得好不好”。日志无报错不等于任务成功；评测下降也需要链路定位究竟是召回、模型、工具还是数据变化。将失败类别与 Trace 关联，建立可复现的问题单，而不是保存全部 Prompt 后无法检索。

## C099 Versioning / Reproducibility（版本管理／可复现性） 【基础】

记录模型标识、采样配置、Prompt、技能、工具 schema、检索配置、索引或数据快照、策略和代码版本。即使温度为零，也不保证跨后端完全重现。目标是能够解释与近似重放，并隔离外部副作用；必要时用录制的工具返回做测试替身。

## C100 Shadow Testing / Canary Release / A/B Testing（影子测试／金丝雀发布／A/B 测试） 【基础】

影子运行复制输入但禁止真实写入，用来比较候选版本；灰度按小范围逐步放量；A/B 使用合理分流与统计方法验证业务效果。影子环境要阻断发信、下单等工具，不只是隐藏结果。模型或知识更新也应进入发布流程，且能够回滚组合版本。

## C101 SLO（Service Level Objective，服务等级目标）/ Error Budget / Kill Switch（错误预算／停用开关） 【基础】

服务目标同时覆盖可用性、时延和任务质量。例如技术接口可用但建议严重错误，业务仍不可用。预算耗尽时限制扩量或回退。为模型、单个工具、单类写操作和租户设置可独立停用的开关；高风险动作异常时优先阻断该动作，保留安全查询能力。

## C102 Feedback / Business Attribution（反馈／业务归因） 【基础】

用户点赞、建议采纳、最终成交和工时节省是不同信号。采纳不一定正确，成交也可能由价格和活动驱动。保存采纳原因、修改内容及最终结果，区分相关性与因果。ROI 应计入人工复核、运维、标注和错误处置成本，必要时通过对照试验归因。

上线资产建议：一份发布清单关联模型、Prompt、数据、工具、策略与评测报告。负责人能够从任意用户投诉定位对应运行，而不是只找到当前版本代码。
