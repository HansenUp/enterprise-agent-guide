# 19 性能与成本

## C103 TTFT（Time to First Token，首个词元时间）/ End-to-End Latency（端到端时延） 【基础】

TTFT 是首个 token 返回时间；用户实际等待还包括排队、检索、工具、审批和多轮推理。流式输出改善感知，不一定缩短完成时间。先画关键路径，减少串行依赖与无效轮次；只有独立且权限允许的子任务才并行，不能并发修改同一订单状态。

## C104 Prefix Cache（前缀缓存）/ KV Cache（Key-Value Cache，键值缓存）/ Semantic Cache（语义缓存） 【条件】

KV cache 复用注意力计算的键值状态；前缀缓存复用公共输入前缀；语义缓存按相似问题复用答案。三者的正确性边界不同。业务答案缓存必须包含租户、用户权限、数据版本和有效期，库存、价格等实时事实不宜因语义相近而复用旧结果。

## C105 Batch Processing / Asynchronous Tasks / Backpressure（批处理／异步任务／背压） 【基础】

离线标签和批量摘要可以排队合批，交互查询则受用户等待限制。背压通过限制队列、并发和速率，阻止流量把模型与工具拖垮。批任务需要逐条状态、失败重试、幂等和取消；“提交成功”不能等同于整批业务完成。

## C106 Model Serving / Quantization / Scheduling（推理服务／量化／调度） 【条件】

Continuous batching 动态合并推理请求，PagedAttention 改善 KV 内存管理，量化降低权重或缓存精度以节省资源。自建推理服务需评估硬件利用率、长上下文、并发和质量变化，不能只比较单请求 token 速度。vLLM 是可评估的服务引擎之一。[S33]

## C107 Cost per Successful Task（单位成功任务成本） 【基础】

每次成功成本＝同一评测窗口的全部相关成本／通过验收的任务数。分子包含失败重试、模型与工具、基础设施和人工复核；不要只算成功请求 token。预算按任务、租户和时间窗分配，设最大轮数与支出。省模型单价却增加失败次数，可能更贵。

## C108 Fallback / Graceful Degradation / Model Routing（故障回退／服务降级／模型路由） 【基础】

模型不可用、预算不足或置信不足时，回退到另一模型、检索原文、确定性流程或人工处理。降级输出需要明确状态。不同模型的工具 schema、上下文能力和拒绝行为可能不同，应分别验证；不能因主模型失败就允许备用模型绕过权限或质量门槛。

优化顺序建议：删除无效步骤 → 减少输入和输出 → 合理检索与缓存 → 可并行工作并行 → 模型路由 → 评估专用微调或自建推理。顺序可因业务约束调整，但每次都应测量质量变化。
