# 20 模型与系统优化

## C109 SFT（Supervised Fine-Tuning，监督微调）/ Behavior Adaptation（行为适配） 【条件】

监督微调用输入与理想输出训练模型，适合稳定任务格式、领域表达和行为模式。最新库存或权限不应靠微调维护，应查询业务系统。先验证问题来自模型能力而非缺失上下文或错误工具；保留独立测试集，评估领域收益和通用能力回退。

## C110 LoRA（Low-Rank Adaptation，低秩适配）/ QLoRA（Quantized Low-Rank Adaptation，量化低秩适配）/ PEFT（Parameter-Efficient Fine-Tuning，参数高效微调） 【条件】

PEFT 是参数高效微调方法族；LoRA 训练低秩适配参数，QLoRA 将量化基础模型与适配训练结合。它们降低部分训练资源需求，但不自动提高数据质量或效果。部署前需确认基础模型、适配器、量化方式及推理服务兼容，并管理其授权与版本。[S34]

## C111 DPO（Direct Preference Optimization，直接偏好优化）/ RL（Reinforcement Learning，强化学习）/ RFT（Reinforcement Fine-Tuning，强化微调） 【条件】

DPO 直接使用偏好对优化；强化学习通过奖励信号优化策略，RFT 常用于以可评分任务进行强化微调。奖励设计错误会导致“刷分”而非业务进步。确定性、可验证任务更适合起步；开放销售建议难以仅用成交结果作为即时奖励，存在延迟和归因问题。

## C112 Distillation / Specialized Model（蒸馏／专用模型） 【条件】

蒸馏用强模型的输出或行为指导更小模型，可降低稳定子任务的成本。教师错误会传递，生成样本需要去重、筛选和人工抽检。适合大量且边界明确的分类、抽取和标准化；不应假设小模型能完整继承教师的开放推理和安全行为。

## C113 DSPy / GEPA（框架与优化器名称）/ System-Level Optimization（系统级优化） 【增强】

把 Prompt、示例与模块组合视为可优化程序，用开发集和评测器搜索配置。GEPA 通过反思反馈改进候选方案，DSPy 提供相应优化支持。收益依赖可靠评测及搜索预算；测试集必须隔离，自动找到的 Prompt 仍应接受安全和维护性检查。[S13]

## C114 Active Learning / Drift / Continuous Improvement（主动学习／漂移／持续改进） 【基础】

主动学习优先选择不确定或有代表性的样本标注；漂移监控观察输入、标签分布及业务关系变化。持续改进可以是更新知识、修复工具、调整 Prompt 或训练模型，不能统称“Agent 自动学习”。生产反馈先进入待审核数据池，避免恶意反馈污染模型与记忆。

选择原则：事实更新用知识和工具；固定步骤用流程；输出行为问题先改提示和示例；稳定规模化能力缺口才评估微调。记住用户偏好、优化 Prompt 和更新模型权重，是三个不同层次。
