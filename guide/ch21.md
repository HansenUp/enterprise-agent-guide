# 21 Coding Agent 与前沿方向

## C115 Coding Agent（编程智能体）/ ACI（Agent-Computer Interface，智能体与计算机交互接口） 【增强】

Coding Agent 能读写仓库、运行工具并根据结果迭代；Agent Computer Interface 指为 Agent 设计的工具和环境交互界面。清晰错误、精确差异、可定位测试结果往往比增加角色更有用。沙箱、分支隔离、代码审查和发布权限决定其能安全做到哪里。

## C116 AGENTS.md / Skills / Hooks（项目指令文件／技能／钩子） 【增强】

仓库说明表达项目约定，技能封装可复用任务知识，Hooks 在事件点执行自动动作。名称和加载规则因产品而异；开放技能格式不保证完整运行时一致。项目规则应有作用域与优先级，Hooks 的权限和失败处理需审计，不能让可编辑规则关闭强制检查。[S16]

## C117 Spec-Driven Development / Validation Gates（规格驱动开发／验证门槛） 【基础】

先给出验收标准，再约束实现、测试和发布。TDD 可用于可明确测试的功能，但模型自己写且自己通过的测试不足以证明正确。用独立验收样本、回归、静态检查和必要人工评审补足。高风险变更的发布许可应由可信流程控制。

## C118 Long-Running Agent / Loop Harness（长时运行智能体／循环执行框架） 【增强】

长任务需要增量目标、进度文件、外部状态、恢复、预算及停止条件。社区所谓 Ralph 类循环通常是重复执行直至条件满足的工程模式，不是统一协议或质量保证。无限重试可能掩盖根因；达到预算、重复失败或需要新授权时应暂停并报告。[S03][S04]

## C119 RLM（Recursive Language Model，递归语言模型）/ Recursive Context（递归上下文） 【探索】

RLM 研究让模型通过程序化访问外部上下文，并递归调用子模型处理片段，以应对超长输入。它与简单增加上下文窗口不同，也不等于所有递归 Agent。潜力在分解与按需读取，但工具安全、递归预算、评测泛化和运行成本仍需按任务验证。[S35]

## C120 Managed Runtime / Agent UI / Proactive Tasks（托管运行时／智能体界面／主动任务） 【增强】

托管运行时将会话、执行环境和调度交给平台；Agent UI 呈现计划、进度、证据、审批和产物；主动任务由事件或定时器触发。三者正在汇合，但协议和产品尚不统一。企业应保留任务状态与产物导出能力，避免将业务唯一记录锁在某个会话接口。[S05]

前沿判断：上下文组织、工具契约、长任务恢复和可验证交付的需求具有持续性；具体 Harness 结构、通信字段、记忆框架及多 Agent 角色划分更容易变化。投资接口与评测资产，比追逐角色数量更耐久。
