# 23 运行契约与可靠执行

以下是平台设计示例，字段名不是行业标准；可以映射到企业已有消息、工作流和审计规范。

| 对象 | 至少需要的字段 | 作用 |
|---|---|---|
| Task | task_id tenant_id actor goal status deadline budget version | 定义任务责任与边界 |
| ToolCall | call_id task_id tool_version args idempotency_key | 定位调用和重复执行 |
| Evidence | source_id source_version locator retrieved_at acl_scope | 支持核验与权限追踪 |
| Approval | approver action_digest scope expires_at decision | 把批准绑定到具体动作 |
| Result | status output evidence_ids side_effects error_code | 区分成功及部分完成 |
| Release | model prompt skill tool policy dataset code_version | 支持回归和回滚 |

## 一次写操作的推荐顺序

1. 验证调用主体、租户、工具权限和参数 schema，检查业务规则及预算。
2. 如需审批，冻结操作对象、参数和摘要；审批通过后再检查有效期与当前业务状态。
3. 使用幂等键调用业务接口，事务内保存结果或进入可核对状态；工具返回业务凭证。
4. 保存审计与证据，更新任务状态；超时不能直接判定写入失败，应查询业务凭证。
5. 未知结果进入人工核对或补偿流程，不能盲目重复扣款、下单或发送通知。

## 状态机示例

CREATED → RUNNING → WAITING_APPROVAL → RUNNING → SUCCEEDED。

RUNNING 也可进入 WAITING_TOOL、FAILED、CANCELLED 或 NEEDS_REVIEW。暂停和终态的定义必须固定；取消不能自动撤回已发生的外部动作。

## 错误契约

区分 INVALID_INPUT、PERMISSION_DENIED、RATE_LIMITED、TRANSIENT_FAILURE、BUSINESS_CONFLICT 和 UNKNOWN_OUTCOME。只有已确认可安全重试的错误才自动重试。错误信息应能帮助模型修正输入，但不要把堆栈中的凭证或内部敏感数据回传。
