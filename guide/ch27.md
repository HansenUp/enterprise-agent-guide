# 27 将 AI Coding 变成团队工程能力

企业推广 AI Coding 时，应同时建设项目规范、隔离运行环境、验证流水线与人工评审机制。采用覆盖率不等于工程收益，需要记录交付周期、缺陷、返工和评审负担。

## 新项目规范

提供明确业务范围、架构边界、目录约定、接口契约、测试方式和发布步骤。将稳定约定放入版本管理的项目说明和技能，将必须执行的检查放入 CI 或可信 Hooks。Agent 完成后交付代码差异、验证证据、遗留问题和回滚说明。

## 老项目规范

先识别现有行为、依赖、数据迁移和隐藏约束，必要时建立特征测试；限定修改范围，避免无关重构。对权限、支付、库存等路径设置更严格验收。仓库中已有约定与通用技能冲突时，明确作用域和优先级，而不是让模型自行猜测。

## 减少能力和 Prompt 差异

把高频需求做成输入模板和可执行流程，让开发人员提交目标、约束与验收条件；把检查工具标准化。提示词范例可以降低差异，但只有可验证的约束、测试和评审才能控制最终质量。保留人工对方案取舍和业务正确性的责任。

## Harness 的效果验证

如果采用多节点、多个子 Agent 和多级门禁，逐项说明每个节点解决哪类失败。用消融测试比较：基础单 Agent、加入项目规则、加入验证门槛、加入子 Agent后的成功率、成本及时延。节点数量本身不代表成熟度。

## 推荐度量

采用率观察普及；从需求到可验收产物的周期观察效率；上线缺陷及返工观察质量；人工审查耗时观察协作成本。按新老项目、任务复杂度和人员经验分组，避免用简单任务的收益外推全部研发工作。

企业平台可以将仓库接入、技能目录、沙箱、验证门槛、产物及审计做成共享服务；业务应用 Agent 则复用身份、工具、评测和运行治理，两者不必共用所有编排逻辑。
