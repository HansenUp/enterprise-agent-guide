# 30 企业 AI 能力平台：范围与三套参考组合

本方案面向多团队共享的知识问答、信息抽取、流程执行、研究分析与软件工程场景。技术资料核验于 2026 年 9 月 11 日。下文“推荐”是基于约束的架构判断，不是市占率排名或经实测证明的全球最佳；未指定企业规模、预算及合规边界，因此先给可裁剪的参考架构。

## AI 平台与 Agent 平台的关系

AI 能力平台统一模型接入、数据处理、推理服务、模型资产、权限、评测和资源治理。Agent 能力平台在其上增加任务状态、工具执行、上下文、人工审批、长任务恢复和产物管理。预测、推荐、OCR、ASR、传统分类器应作为能力服务接入，不必全部包装成自主 Agent。

业务入口包含聊天、表单、批量导入、业务系统 API 与事件触发。平台产出应是可验证的回答、结构化数据或业务动作，而不是只有聊天消息。确定性流程、单 Agent 与多 Agent 共存，共用治理和能力目录。

## 三套组合：选一套起步

| 组合 | 推荐配置 | 适用边界与升级触发 |
|---|---|---|
| A 最小可用平台 | TypeScript 前端；Python FastAPI + Pydantic；一个有限循环或显式状态机；PostgreSQL + pgvector；对象存储；已批准模型 API；现有 SSO；基础追踪和评测 | 单团队、低风险、短任务。已有容器服务即可。跨天审批或复杂恢复出现后增加持久化编排；不按人数机械升级 |
| B 标准生产平台（默认参考） | A + LangGraph；独立任务与工具服务；模型网关；身份和策略执行；离线知识流水线；OTel + Langfuse；按需引入 Temporal；现有生产容器平台 | 多团队共享、有写操作、需审计恢复。检索、推理、采集按负载独立扩容；高可用数据服务是前提 |
| C 严格私有化平台 | B + 内网模型服务 vLLM 或 SGLang；GPU 资源池；内部镜像/依赖仓库；离线模型资产；全链路本地评测和遥测 | 数据禁止外发或持续稳定负载。需承担模型许可、GPU容量、升级、容灾和质量责任；开源权重不等于无限制商用 |

三套组合描述组件职责，不要求每项都是单独微服务。先用模块化单体加独立 worker，按隔离、扩容、责任归属再拆分。若已有成熟 Java 或 .NET 平台，业务控制面沿用现有技术，AI 执行面通过契约接入。

## 建设与采购边界

自建企业特有的授权映射、业务工具、领域知识治理、评测数据、发布门禁和产品交互。优先复用数据库、身份、消息、可观测性和工作流设施。托管模型、托管运行平台或低代码平台可加速交付，但必须验证私网连接、数据保留、任务导出、审计和退出能力。

Dify 可作为业务人员创建知识应用与流程的入口；工程团队保留核心工具权限及发布管控。n8n 可作为连接与自动化候选，不应直接承载未经审批的高权限动作。两者许可都不能简单等同于无条件 Apache/MIT；对外 SaaS 或嵌入产品前检查实际许可。[S60][S61]
