# 33 模型、知识、记忆与数据工程方案

## 模型选型不能只看排行榜

建立任务能力矩阵：中文与领域理解、结构化输出合法率、工具参数正确率、长上下文证据定位、多模态、拒答质量、延迟、可用区域和数据使用条款。使用企业脱敏独立测试集比较已批准的商业 API 与开源权重模型；不固定某个型号为长期最优。

推荐先用质量达标的强模型建立基线，再把分类、路由和摘要迁移到小模型；嵌入模型与重排模型独立评测。模型路由必须同时检查数据分级、能力和成本，故障降级不能绕过数据出境或任务安全边界。

自托管比较 vLLM 与 SGLang 时固定权重、量化、输入输出分布、并发、GPU 与精度要求。观测首 token 时间、每 token 时间、吞吐、错误和 OOM。OpenAI 兼容接口不代表工具调用、缓存、推理预算等语义完全一致。[S33][S62]

## 知识入库流水线

数据源授权 → 拉取或变更同步 → 原文对象存储 → 解析/OCR → 清洗去重 → 结构化分块 → 分类与敏感字段识别 → 嵌入 → 索引构建 → 小流量检索验收 → 原子切换知识版本。

每个 chunk 保存 tenant_id、doc_id、revision、页码/坐标、hash、source_uri、ACL 引用、parser_version、embedding_version、有效时间和删除状态。索引是派生物；保留原文与解析产物才能重建与迁移。

Docling 是解析候选而非所有文档的通用解法；用真实合同、扫描件、表格、图文混排建立解析基准。[S49] 删除与权限撤销必须传播到索引、缓存、摘要和产物，并测试传播延迟。

## 检索执行链与升级依据

先确定用户授权范围和结构化过滤条件，再做关键词与向量召回，融合排序后可选重排，最终返回有定位的证据。pgvector 支持在 PostgreSQL 中进行相似检索；近似索引与过滤组合需要实测，不可只测无过滤 top-k。[S47]

中文关键词检索需验证分词与同义词；PostgreSQL 全文默认配置不能直接假定满足所有中文需求。当关键词、过滤聚合或搜索团队能力要求更高时评估 OpenSearch；向量负载独立增长时比较 Qdrant。[S48][S57]

只有基准表明跨实体、多跳关系问题无法通过普通检索解决，再引入 GraphRAG/知识图谱；把抽取、更新、实体消歧、权限和图索引费用纳入总成本。长上下文也需与 RAG 对照，不自动替代权限过滤与数据更新。

## 记忆与训练数据

会话状态存在任务数据库；长期用户偏好是带来源、有效期和删除能力的独立记录；业务事实在主系统；可检索知识在知识服务；过程产物在对象存储。检索历史摘要时重新校验权限，不能因为“曾经可见”而继续展示。

用户反馈先去标识、授权审查和去重，再进入评测或训练。训练集与测试集严格隔离；时间切分检查漂移。微调适合稳定格式、风格与任务行为，持续变化的业务事实优先检索或工具查询。
