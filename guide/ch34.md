# 34 服务契约、状态与安全实现

## 最小服务接口

| 接口示例 | 用途 | 必需约束 |
|---|---|---|
| POST /v1/runs | 提交任务，返回 202 与 run_id | 服务端解析租户；Idempotency-Key；版本与预算快照 |
| GET /v1/runs/{id} | 查询状态、错误和产物引用 | 对象级授权；不返回其他用户上下文 |
| GET /v1/runs/{id}/events | 可恢复的流式进度 | 事件序号、断线续传；连接断开不等于取消任务 |
| POST /v1/runs/{id}/cancel | 请求取消 | 明确 cancel_requested 与已取消；说明副作用状态 |
| POST /v1/approvals/{id}/decision | 批准或拒绝提案 | 审批者权限、参数哈希、有效期、防重放 |
| POST /v1/tools/{name}/execute | 内部执行已授权工具 | 不直接暴露给匿名前端；独立校验与操作记录 |
| POST /v1/knowledge/search | 授权检索 | ACL 先过滤；证据与知识版本；查询预算 |

以上是参考契约，非特定产品现成 API。若暴露 A2A，需增加协议适配与授权范围约定。模型生成的 tenant_id、user_id、role 等字段不得覆盖可信身份上下文。

## 核心数据实体

Tenant / Application / Release：租户、应用、不可变配置和策略引用。Run / Step / Event：任务状态、尝试次数、owner lease、截止时间与事件序号。ToolOperation：幂等键、参数摘要、业务返回、状态和对账记录。Approval：提案哈希、审批身份、期限与撤销信息。Artifact / Evidence：对象路径、版本、来源、ACL 和留存期限。EvalDataset / EvalRun：数据集快照、评测配置、结果和评审人。

Run 状态建议：queued → running → waiting_approval → running → succeeded；同时支持 failed、cancel_requested、cancelled、expired。数据库事务与条件更新限制状态跃迁；worker lease 过期后由新 worker 接管，旧 worker 需通过 fencing token 等机制避免重复提交。

## 权限与隔离必须落到执行层

SSO 解决身份，策略服务判断动作是否允许，工具执行器在动作发生时执法。Keycloak 与 OPA 分别可承担身份和策略能力，但领域权限映射需要企业实现。[S52][S53]

共享数据库至少包含 tenant_id、复合唯一约束和访问约束；高隔离租户可使用独立数据库/部署。缓存键包括租户、权限版本、知识版本与模型配置；输出日志同样受数据权限与留存控制。

Kubernetes namespace 不是完整安全边界；需要网络策略、服务身份、资源配额与适当的运行隔离。[S54] 不可信代码使用短生命周期沙箱、只读基础镜像、受限网络、资源限额和临时凭据。gVisor 可增加内核接口隔离，但仍需验证系统调用兼容性并控制数据与出口。[S55]

## 提示注入与供应链

把检索文档、网页、邮件、工具结果视为数据来源；来源文本不能授予权限。固定可用工具集合，输出参数校验，工具执行前校验身份和业务条件。内容检测可辅助拦截，不作为唯一防线。依赖、模型、MCP 服务和技能建立来源登记、版本锁定、审查、签名或校验与撤销机制。

禁止在日志保存长期密钥或默认保存完整敏感提示。秘密由可信服务获取，按任务注入短期凭据。对外工具实行域名白名单和数据分类检查，防止借合法 HTTP 工具泄露数据。
