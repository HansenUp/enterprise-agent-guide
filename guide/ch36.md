# 36 部署、容灾与 90 天实施计划

## 生产部署拓扑

接入区运行前端和 API 网关；应用区运行控制面、Agent worker、检索与工具适配；数据区运行数据库、对象存储、索引；受限执行区运行沙箱；自托管场景增加 GPU 推理区。开发、测试、生产的凭据和数据分别管理。

已有 Kubernetes 平台时复用其发布与监控能力；没有运维团队时，托管容器和托管数据库通常更适合起步。CI/CD 使用企业现有工具，部署描述、数据库迁移与策略均版本化；镜像固定 digest，禁止生产自动跟随 latest。

无状态 API 多副本，worker 按队列等待和吞吐扩容；GPU 按模型负载扩容。数据库与状态存储提供备份、故障切换与恢复演练；索引可重建，但原文、ACL、业务操作账本不能依赖索引恢复。

## 恢复目标与故障演练

示例目标可设核心任务元数据 RPO ≤ 5 分钟、RTO ≤ 60 分钟，但这是待业务确认的设计目标，不是软件开箱保证。业务写操作需按外部系统交易记录对账，即使任务状态丢失也不能重复扣减或发起审批。

演练 worker 在工具提交后崩溃、数据库主节点失效、模型 API 429/超时、向量索引落后、权限撤销、审批过期、对象存储不可用及密钥轮换。每类故障明确停止、降级、重试、补偿与人工接管条件。

严格内网环境还需镜像/包/模型离线更新流程、许可证镜像留档、漏洞修补、GPU 驱动兼容验证。自托管不消除供应链风险，也不会自动带来低成本。

## 分阶段交付与责任

| 阶段 | 交付 | 验收与责任 |
|---|---|---|
| 第 1–2 周 | 场景与风险分级、数据地图、评测种子集、模型/框架 PoC | 业务负责人定义成功；架构与安全确认边界 |
| 第 3–4 周 | 一个只读知识应用、身份接入、证据链、基础追踪 | 领域专家验证事实；数据负责人验证权限和删除 |
| 第 5–8 周 | 受控写工具、审批、任务恢复、版本化发布、成本看板 | 平台与 SRE 演练故障；业务验收误操作边界 |
| 第 9–12 周 | 第二种场景复用、灰度、容灾演练、运营机制 | 用复用率和业务收益证明平台价值；评审下一阶段 |

90 天是首批闭环的参考节奏，不保证所有企业能同期交付完整平台；完整建设方案的多阶段范围更大，应以能力出口重新估算。关键角色包括业务产品、平台后端、数据/检索、AI 评测、前端、SRE、安全与领域专家；可由同一成员兼任，但职责不能缺失。

## 平台交付物清单

应用模板、开发 SDK、工具目录、知识接入规范、版本化 Agent 定义、任务/审批契约、权限矩阵、评测数据与流水线、追踪看板、容量与成本模型、发布回滚手册、事故与恢复手册、数据删除流程、组件许可证与版本清单。

平台成功标准是第二和第三个业务应用能复用上述资产，并保持质量与权限标准。只交付聊天门户和一组模型 API 还不构成完整企业能力平台。
