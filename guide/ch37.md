# 37 选型决策记录、生命周期与演进路线

## 用可解释的决策代替“最流行”

先设硬门槛：数据部署位置、模型许可、语言支持、身份隔离、必要工具能力、恢复语义与预算；未通过者不进入评分。再以同一测试集评估业务质量、可靠性、安全、开发效率、总成本和退出能力。

参考权重可以是质量 30%、安全治理 20%、可靠性 20%、团队适配 15%、成本 10%、退出能力 5%，由业务风险调整。记录样本、环境、日期与失败案例；未知项留空，不把宣传资料当满分。分数只辅助判断，不能抵消硬门槛失败。

## 每项选择都留一份 ADR

决策记录包含：场景与约束、考虑的替代、证据和压测结果、采用方案、放弃方案的原因、所有者、版本/许可、可接受风险、复审日期和触发条件。例如“先用 pgvector；当授权过滤后的检索 p95 超过目标且优化无效，或检索负载需独立扩容时，评估 Qdrant/OpenSearch”。

## 生命周期标记

| 标记 | 处理方式 | 典型含义 |
|---|---|---|
| 长期基础 | 持续建设，降低产品耦合 | 契约、权限、幂等、证据、评测、可观测性 |
| 持续发展方向（判断） | 重点跟踪，用结果验证 | 上下文工程、可靠运行、类型化工具、人机协作、模型路由 |
| 条件采用 | 满足约束并证明增益再上 | 多 Agent、GraphRAG、微调、自托管 GPU、A2A |
| 探索 | 隔离试验，不承载核心承诺 | 全自主长程任务、自我修改、多智能体开放协商 |
| 官方迁移/停用 | 按公告与兼容测试迁移 | 查本指南技术演进及具体产品官方公告；不要把某版本弃用扩展成概念消失 |

新框架持续变化，但企业资产应保持可导出：工具采用独立 schema，知识保存原文和版本，评测可重跑，任务有通用状态和产物，模型调用保留提供方能力差异。升级模型、框架、协议或嵌入模型，都属于需要回归测试的发布。

## 许可证与版本验收

Dify 使用附加条件的许可；n8n 使用 Sustainable Use License 等许可机制，不能在技术目录中不加区分地标为宽松开源。[S60][S61] 各组件社区版、商业功能和托管服务的权利与能力分别确认；模型权重、训练数据和依赖包也各有条款。

本文不给未经组合验证的“全栈最新版本号”。上线时维护 BOM：项目 URL、实际版本/commit、许可证、漏洞检查日期、支持周期、负责人、升级回归和回滚路径。官方文档说明能力；本方案中的推荐组合还需企业 PoC 和生产压测证明。
