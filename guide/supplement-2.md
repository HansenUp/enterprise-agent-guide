# 补充概念二 平台与交互

## RBAC / ABAC / ReBAC（基于角色／属性／关系的访问控制） 【基础】

RBAC 按角色授权；ABAC 按用户、资源、时间等属性决策；ReBAC 按对象关系授权，例如销售与客户归属。企业可能组合使用。模型只表达申请，可信权限服务作最终判断；属性或关系变化后，长期任务和缓存必须重新验证。

## LLMOps / AgentOps / FinOps（模型运维／Agent 运维／成本运营） 【基础】

LLMOps 管理模型应用的版本、数据、评测和运行；AgentOps 进一步关注多步动作、轨迹、工具与任务恢复；FinOps 关注成本分配与业务价值。这些是职责组织方式，边界并无统一定义。没有必要因此建设三套重复平台，关键是负责人和数据能闭环。

## Model Gateway / Semantic Router（模型网关／语义路由） 【增强】

模型网关统一接入、凭证、配额、路由和计费记录；语义路由根据请求含义选择模型或业务流程。网关不应隐去模型差异，路由也需要准确率与回退测试。供应商服务不可用和任务不适合某模型，是不同路由原因。

## Ontology / Knowledge Graph / Semantic Layer（本体／知识图谱／语义层） 【基础】

本体定义实体、关系及约束；知识图谱保存具体实体关系；语义层统一业务指标与查询含义。品牌、菜品、原料关系可用图表达，“销售额”口径由业务语义层确定。GraphRAG 是利用图结构支持检索的一类方法，不等于所有知识图谱应用。

## Realtime Voice / VAD / Barge-in（实时语音／语音活动检测／插话打断） 【条件】

实时语音 Agent 需要语音活动检测、轮次判断、打断处理和低时延反馈。用户打断后应停止旧响应，并检查已触发动作是否仍应继续。销售录音离线分析不需要全部实时机制；从录音分析升级为自主外呼，会显著增加交互与动作治理要求。

## AG-UI / A2UI / Generative UI（Agent 前端交互协议／声明式界面描述／生成式界面） 【探索】

AG-UI 规范 Agent 与前端之间的事件和状态交互；A2UI 用声明式描述传递可渲染界面，两者可以组合。它们与 MCP Apps 的集成边界不同，不能因名称相似而混用。界面组件应由受控渲染器校验，确认动作必须落到服务端审批记录；还需验证断线、取消与状态同步。[S43][S44]
